## Security

| Resource | Inbound | Outbound |
|----------|---------|----------|
| EC2 SG | Port 22 from `186.30.138.158/32` only | All |
| RDS SG | Port 5432 from EC2 SG only | None needed |

No 0.0.0.0/0 anywhere. RDS has no public endpoint. EC2 is the only entry point.

## EC2 Instance

- AMI: Amazon Linux 2023 (latest, resolved via `data "aws_ami"` — no hardcoded ID)
- Instance type: `t3.micro` (staging) / `t3.small` Reserved 1yr (prod)
- User data installs on first boot:
  - Python 3.11 + pip
  - Node 20 + PM2
  - Amazon CloudWatch agent
  - postgresql-client (for manual RDS access from EC2)
- Storage: 20 GB gp3, encrypted
- IAM instance profile: `behemoth-staging-ec2`

## RDS PostgreSQL

- Engine: PostgreSQL 15
- Instance: `db.t3.micro`
- DB name: `behemoth`
- Username: `behemoth_app`
- Password: auto-generated by `random_password`, stored in SSM at `behemoth.staging.db.password`
- Private subnet only — not publicly accessible
- Backups: 7-day retention
- Deletion protection: off (staging)

## IAM Instance Profile

Role `behemoth-staging-ec2` allows EC2 to:
- `ssm:GetParameter` + `kms:Decrypt` on `behemoth.staging.*` parameters only
- `logs:PutLogEvents` to `/behemoth/*` CloudWatch log groups

No wildcard permissions. No S3. No other services.

## Secrets — SSM Parameter Store

All secrets use `SecureString` (AES-256 via default KMS key). Free tier.

| Parameter | Managed by | Purpose |
|-----------|-----------|---------|
| `behemoth.staging.binance.apiKey` | Manual | Binance demo API key |
| `behemoth.staging.binance.secret` | Manual | Binance demo API secret |
| `behemoth.staging.slack.webhookUrl` | Manual | Slack notifications |
| `behemoth.staging.db.password` | Terraform | RDS password (auto-generated) |

## Terraform State

- Backend: S3 bucket `eccensia-tfstate-trading-staging`
- Key: `trading/staging/terraform.tfstate`
- No DynamoDB lock (solo dev, single pipeline)
- Versioning + encryption enabled on bucket

## CloudWatch

Log groups (30-day retention):
- `/behemoth/bot` — PM2 stdout
- `/behemoth/errors` — PM2 stderr

## Key Decisions & Why

| Decision | Why |
|----------|-----|
| SSM over Secrets Manager | $0 vs $0.40/secret/mo. SSM SecureString free tier is sufficient. |
| No DynamoDB lock | Solo dev. Single GH Actions pipeline. Lock adds cost for zero benefit. |
| t3.micro staging / t3.small prod | Right-sized. Bot is IO-bound, not compute-bound. |
| RDS not Lambda/serverless | Persistent candle log + cycle state. Needs ACID, not event processing. |
| No Multi-AZ RDS staging | Cost. Prod will have it. |
| Private RDS subnet | Defense in depth. EC2 is the only database client. |
| OIDC for GH Actions | No stored IAM keys. Credentials live 15min per job. |
